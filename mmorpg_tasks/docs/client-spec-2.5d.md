## 1. 为什么是 2.5D（而非纯 2D / 全 3D）

1. **保留「不生产 3D 模型」的核心优势**：RFC §6 / §9.1 已明确 3D 几何 / 贴图生产是整链最大不可自动化项。2.5D 的世界用程序化网格 + 2D 精灵承载，美术量仍接近 2D，不引入 Blender / 建模工具 / 骨骼动画外包的瓶颈。
2. **获得 3D 的关键收益**：透视 / 等距相机带来纵深感；**Godot 3D 深度缓冲让墙后的精灵自然被遮挡**——这是纯 2D 的 Y-sort 做不到的，对 MMORPG 的场景层次感是质变。
3. **成本适中**：不需要全 3D 的角色蒙皮 / 骨骼动画 / 光照烘焙 / 材质系统；相机 + 深度 + billboard 管线是低风险增量。这正是 RFC §9.7-4 早已预留的「2.5D 过渡档」，现提升为当前正式形态。

> 与 RFC §9.6 同源的纪律仍然最高优先：**逻辑层不得解算表现**。位置 / 朝向 / 状态一律由服务端数据与配置驱动，客户端表现层只做「把数据翻译成画面」。守住这条，未来若需进一步升级到全 3D，只需替换表现层（精灵 → 模型、程序化网格 → 地形网格），逻辑与网络层零改动。

## 2. 2.5D 技术定义

### 2.1 世界坐标
- 全部实体 / 地形使用 `Vec3(x, y, z)`；服务端快照 `position` 直接映射为 `Node3D.global_position`，**不做 2D 网格 ↔ 3D 坐标的二次换算**。
- 高度（地形起伏）由地面网格的高度图表达，实体 `z` 取自服务端下发的高度或 AOI 快照。

### 2.2 相机
- 使用 `Camera3D`（Perspective，**固定俯角 45°（用户决策）**）；可 4 / 8 向旋转或锁定。
- `near` / `far` 按视距预算（Low ≈ 80m，High ≈ 250m）配置；避免过大 far 导致深度精度差 / 近裁面穿模。
- 相机跟随玩家，带简单阻尼（插值），不每帧硬切。

### 2.3 深度遮挡
- 依赖 Godot 3D 深度缓冲：被墙体 / 地形遮挡的精灵自动不可见；透明精灵开启深度写入（或半透明排序）以避免错误穿透。
- 这是 2.5D 相对纯 2D Y-sort 的主要观感跃升点，也是验收重点之一。

### 2.4 精灵表现
- **角色 / 怪物 / NPC**：`Sprite3D`（`BillboardMode::ENABLED` 永远朝相机，或 `FIXED_Y` 锁定 Y 轴旋转做等距朝向）；动画用 `AnimatedSprite3D`。朝向由**翻转纹理**或**旋转 billboard**实现，不依赖 3D 骨骼。
- **地面 / 地形**：`MeshInstance3D`（PlaneMesh / 高度图网格），贴 **TileSet 纹理图集**，程序化生成，**无 DCC 建模**。
- **道具 / 建筑**：远处用 billboard 精灵；近处需遮挡 / 拾取时改用简单 3D 基元（`Box` / `Cylinder` / `CSG`）。

### 2.5 光照
- 1 个方向光 + 环境光，**无实时阴影**（与 Low 档纪律一致）；精灵可接受平面光或保持平直（billboard 不受法线影响，观感稳定）。
- 如需更立体，可在地面网格上烘焙顶点色 / 简单 AO，不引入实时全局光照。

## 3. 渲染架构与三档画质

- **渲染器 = Godot Compatibility（OpenGL 3.3 / D3D11）单档**。2.5D 的深度 / 透视相机在 Compatibility 下完全可用，不依赖 Forward+（Vulkan / D3D12）。Forward+ 仍作为未来全 3D 阶段的承接基线保留，但本阶段不启用。
- 画质三档通过 `QualityPreset` 配置化（禁止硬编码）：

| 项 | Low | Medium | High |
|---|---|---|---|
| 纹理上限（图集 / 贴图） | 512 | 1024 | 2048 |
| 地面网格密度 | 低（大格子） | 中 | 高（小格子 + 细节） |
| LOD / 远精灵降级 | 激进 | 中 | 关 |
| 阴影 | 关 | 关 | 关（环境光近似） |
| 同屏实体 | 50 | 150 | 300 |
| 粒子数 | 200 | 1000 | 3000 |
| 网络更新率 | 10Hz | 20Hz | 30Hz |
| 视距 | 80m | 150m | 250m |
| 区块半径 | 1 | 2 | 3 |
| 纹理预算 | 256MB | 512MB | 1GB |
| 网格预算 | 128MB | 256MB | 512MB |

## 4. 性能预算口径（2.5D）

原 3D 口径（DrawCall / 三角面 / LOD / 阴影）与纯 2D 口径（图集切换 / Canvas 重绘）都不完全适用，2.5D 取并集：

- **DrawCall** 与 **图集 / 材质切换次数**（精灵靠同图集合批 + `Sprite3D` 批处理；地面网格按区块合批）
- **三角面数**：地面网格 + 3D 基元之和（Low 档目标 < 300k；地面网格密度是主要变量，必须预算硬控）
- **同屏精灵 / 图元数** 上限
- **纹理显存**（图集分辨率之和）与 **音频常驻 / 流式** 划分
- **深度预处理 / 透明排序** 开销（大量半透明精灵时）
- **Low 档目标**（4 核 / 4GB RAM / 1GB VRAM / 传统 DX11 GPU）：2.5D 下从「激进值」变为**可达值**——但**仍需实测容量报告（TASK-036 交付）**，不得未测先宣称兼容某硬件。

## 5. 美术资产策略（不生产 3D 模型）

- **角色 / 怪物 / NPC**：**8 向** 2D 精灵图集（PNG，带 alpha：上 / 下 / 左 / 右 + 四斜向，用户决策）+ `AnimatedSprite3D`。朝向翻转为实现，无需 3D 骨骼。
- **地面 / 地形**：程序化 3D 网格（高度图 / 网格面，Godot `MeshDataTool` 或自定义生成），贴 TileSet 纹理图集。**这是 2.5D 唯一需要的「几何」生产，且为程序化，不依赖美术建模。**
- **道具 / 建筑**：billboard 精灵（远处）或简单 3D 基元（近处需遮挡 / 拾取）。
- **UI 图标**：SVG / PNG，沿用 2D 口径。
- **AI 协作边界**（RFC §6）：AI（WorkBuddy）直接生成 / 校验 **GDScript 代码、.tscn 场景、资源导入配置、程序化网格脚本**；**不生成 3D 几何模型本身**。资产生产（8 向精灵图集、TileSet 纹理）走外购 / AI 出图工具 / 免费包。

## 6. 坐标 / 相机 / 输入

- **相机**：`Camera3D` 透视、固定俯角 45°、阻尼跟随（见 §2.2）。
- **输入**：键鼠 / 手柄抽象，逻辑帧开始采样一次；屏幕 → 世界射线用于地面拾取 / 选中（Godot `camera.intersect_ray`）。
- **移动表现**：客户端只持有服务端镜像快照，位置用 100ms 插值缓冲平滑播放；短时丢包用外推（上限 200ms，超出冻结）。**不做权威判定**（伤害 / 命中 / 掉落由服务端裁定）。

## 7. 目录分层与依赖单向（保持不变）

```
client/runtime/      —— 核心运行时（autoload，不依赖任何上层）
client/network/      —— 传输与协议（依赖 runtime）
client/gameplay/     —— 战斗 / 技能 / 任务表现（依赖 runtime + network）
client/ui/           —— UI 层（依赖 runtime + gameplay，反向禁止）
client/extensions/   —— GDExtension(C++) 构建产物与绑定（依赖 runtime）
```

依赖方向即目录引用方向；验收脚本用静态扫描强制单向（禁止 `client/ui/` 反向 import 上层目录）。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Compatibility 渲染器 3D 能力有限 | 大场景 / 复杂光照受限 | 本阶段只用透视相机 + 深度 + billboard，不依赖高级特性；规范 §20/§35 明确「优先低资源非高画质」 |
| billboard 朝向伪影（近大远小 / 侧视穿帮） | 观感瑕疵 | 角色用 `FIXED_Y` 等距朝向（45° 俯角下 8 向精灵覆盖主要视角）；建筑近处改 3D 基元 |
| 地面网格密度 vs 预算 | 三角面 / 显存超 Low 目标 | 网格密度进 `QualityPreset`，按档硬控；实测后写入容量报告 |
| 同屏精灵数 vs DrawCall | 2.5D 下精灵仍需合批 | 同图集 `Sprite3D` 批处理 + 远精灵降级 / 剔除 |
| 深度排序与半透明 | 透明精灵穿透 / 排序错 | 透明材质开启深度写入或显式排序层 |
