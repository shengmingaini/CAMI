# RFC：Live Scene Migration（实时场景迁移）

状态：Phase 2 候选（第一版不做）
提出日期：2026-08-29
相关任务：TASK-037（第一版仅做重连 + Checkpoint 恢复）

---

## 1. 背景与张力

- 根规范 §1「项目目标」列出：**Scene 可以独立迁移**。
- 根规范 §34「GameNode 故障迁移」明确：**第一版本只要求玩家重连、重新进入新 GameNode 并恢复最近一次可靠持久化状态**；Live Scene Migration 在后续阶段实现。
- TASK-037 按 §34 执行，明确不做实时状态迁移。

两处表述存在张力：§1 把"Scene 独立迁移"当作目标，§34 把它降级为 Phase 2。
**在规范层未澄清前，以 §34 为实施依据**（更具体、且是分阶段约束），§1 的措辞待统一修订。

## 2. 第一版交付（现状）

- 玩家从故障 GameNode 重连 → 进入新 GameNode → 从 Checkpoint（默认 30s）或持久化数据恢复。
- 可能回退到最近 Checkpoint（丢失窗口内 delta），已写入 TASK-037 验收与文档。
- 不做 Scene 实时状态在节点间搬运。

## 3. Phase 2 待解决问题（本 RFC 范围）

1. **Scene 状态序列化**：把 Scene 的完整实时状态（Entity/Component/Movement/AOI/Buff/临时状态）可序列化、可传输。
2. **迁移协议**：Scene Owner 单点移交（禁止双写），含状态校验与一致性哈希。
3. **零/低中断**：迁移期间玩家不感知断连，或仅短暂重连（目标 < 1s）。
4. **触发策略**：节点过载/下线/运维调度时，由 ControlService（TASK-040）发起迁移决策。
5. **回滚**：迁移失败时回退到源节点（保留源节点冻结态直到目标确认）。
6. **测试**：真实 kill 目标节点 → Scene 迁移到新节点 → 玩家状态一致。

## 4. 接口兼容性约束（与 §27 对齐）

- 迁移机制不得破坏既有 Scene/Entity 接口契约（TASK-012/011 的 `include/` 冻结头）。
- 序列化必须复用 TASK-005 的 Codec（Protobuf/FlatBuffers），新增 Scene 状态字段带 `version`。
- 新增迁移能力走注册表/扩展点，禁止修改 TASK-012/037 既有文件。

## 5. 验收门禁（Phase 2 新增）

- 真实节点下线 → Scene 迁移完成 < 目标延迟；玩家 Entity 状态（HP/位置/Buff/背包）零丢失。
- 迁移中源节点冻结、目标确认前禁止双写。
- 迁移失败可回滚，不丢数据。
