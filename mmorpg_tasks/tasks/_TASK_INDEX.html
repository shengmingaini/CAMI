MMORPG 任务总览（TASK-000 ~ TASK-041）

全部 42 个任务，当前状态：全部 PENDING（无 DONE）。 本地源: F://AI//workbuddy//CAMI//mmorpg_tasks//tasks// 每个任务独立 .md 文件，含完整 Objective/依赖/验收/接口契约/提交规范。

Phase 0 · 工程基础 5 个任务

TASK-000PENDING项目初始化与仓库规范
模块: build / repo · 依赖: 无
建立整个项目的统一工程规则与空工程骨架：目录结构、根 CMake 工程、Debug/Release 双构建、基础 CI、以及 PROJECT_REQUIREMENTS.md / ARCHITECTURE.md / DEVELOPMENT.md 三份最高级规范文档。本任务**不实现任何游戏功能**。
TASK-001PENDINGCore Error / Result 系统
模块: engine/core · 依赖: TASK-000
统一整个项目的错误处理：提供 Result / ErrorCode / Error 三件套与 9 个标准错误码，服务端与客户端共用同一套定义，禁止任何模块自行设计冲突的错误体系。
TASK-002PENDINGCore Logger / Trace
模块: engine/core · 依赖: TASK-001
实现统一 Logger 与 TraceID 传播机制，使同一请求的全部日志可通过 TraceID 串起来；日志字段固定为 Timestamp/Level/Service/Module/TraceID/RequestID/PlayerID/SceneID/Message。
TASK-003PENDINGCore Time / UUID / Config
模块: engine/core · 依赖: TASK-000
实现 Time（MonotonicClock / WallClock）、UUID 生成与 ConfigManager。**特别要求：游戏 Tick 计时只能基于 MonotonicClock，禁止使用系统墙钟作为唯一计时依据。**
TASK-004PENDINGCore Memory / Thread / Scheduler
模块: engine/core · 依赖: TASK-001, TASK-003
建立线程模型与执行骨架：Thread 抽象、Task 提交、Scheduler 定时任务、ObjectPool / MemoryPool / Arena 内存设施，并固定四类线程（Network / Simulation / Worker / Persistence）。

Phase 1 · 统一通信 3 个任务

TASK-005PENDINGProtocol Schema（Protobuf + FlatBuffers）
模块: protocol · 依赖: TASK-001
定义全项目唯一的消息契约：MessageEnvelope / Command / Query / Event 的 Protobuf 定义，以及高频游戏数据的 FlatBuffers 定义。C++ 侧可 Encode / Decode / Validate / Version Check。这是后续所有跨进程与客户端通信的唯一真相源。
TASK-006PENDINGRPC Framework（gRPC 统一封装）
模块: engine/rpc · 依赖: TASK-001, TASK-005
封装统一 gRPC 客户端/服务端：超时、取消、重试、错误映射（gRPC status ↔ mmo::core::Error）。**RPC 只允许用于跨进程、低频、管理面与数据面；禁止在战斗 Tick 内使用同步 RPC。**
TASK-007PENDINGCommand / Query / Event Bus
模块: engine/core · 依赖: TASK-001, TASK-004, TASK-005
实现进程内三条总线：CommandBus（执行操作）、QueryBus（只读查询，无副作用）、EventBus（已发生的事实，异步处理）。提供 Register / Dispatch / Subscribe / Unsubscribe，并跑通 Command→Handler→Event→Subscriber 的 Demo 链路。

Phase 2 · Gateway 3 个任务

TASK-008PENDINGNetwork Transport（TCP 第一版）
模块: engine/net · 依赖: TASK-004, TASK-005
实现 INetworkTransport 抽象与 TCP 第一版实现：Connection / Packet / Buffer / Encode / Decode / Send / Receive，并通过 1K / 5K / 10K 连接基准测试。未来可扩展 UDP / QUIC 而不改动上层。
TASK-009PENDINGSession 管理
模块: server/gateway · 依赖: TASK-008
实现 Session 与 SessionManager：会话生命周期、鉴权、心跳、断线处理与重连准备。Session 字段固定为 SessionID / PlayerID / GatewayID / GameNodeID / SceneID / Version。
TASK-010PENDINGGateway Router
模块: server/gateway · 依赖: TASK-007, TASK-009
实现 Gateway 路由层：PlayerRouter（PlayerID→GameNode）、SceneRouter（SceneID→GameNode）、NodeRegistry（节点注册与健康）、RouteCache。验收目标是跑通 Login → Gateway → GameNode → Scene 全链路。

Phase 3 · GameNode Core 5 个任务

TASK-011PENDINGEntity System
模块: server/gamenode/entity · 依赖: TASK-004, TASK-007
实现统一实体系统：EntityID / EntityType / SceneID / Position / Components，支持 Create / Destroy / Find / AttachComponent / RemoveComponent。第一版采用 ECS-like Component 思想，不强制完整 ECS 框架。
TASK-012PENDINGScene System
模块: server/gamenode/scene · 依赖: TASK-011
实现 Scene 与 SceneManager：场景生命周期（Creating/Loading/Running/Draining/Destroying）与场景标识（SceneID / SceneVersion / TickNumber / StateHash / OwnerGameNode）。Scene 是实时仿真的基本单位。
TASK-013PENDINGSimulation Scheduler（20Hz 固定 Tick）
模块: server/gamenode/scheduler · 依赖: TASK-003, TASK-004, TASK-012
实现 GameNode 固定 20Hz Tick 调度：Input → Movement → AOI → Combat → Buff → Quest → Event → Replication 八阶段顺序执行，且**每个阶段独立计时统计**。
TASK-014PENDINGAOI System（Dynamic Grid 第一版）
模块: server/gamenode/aoi · 依赖: TASK-011, TASK-012
实现 AOI 系统，第一版用 Dynamic Grid 算法，提供 Enter / Leave / Move / QueryVisible / Broadcast 五个统一接口，并在 100 / 500 / 1000 / 2000 实体下测量查询延迟、广播成本与内存。
TASK-015PENDINGMovement System
模块: server/gamenode/movement · 依赖: TASK-011, TASK-014
实现移动系统：Move / Direction / Speed / Position / Velocity 与移动校验（防作弊）。**禁止数据库访问。**
