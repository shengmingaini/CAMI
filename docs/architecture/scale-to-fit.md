# Scale-to-Fit：最小资源起步 + 线性扩容架构方案

> **版本**: v1.0 | **日期**: 2026-08-12 | **决策**: 逻辑 8 分片固定 · 物理实例渐进；Redis 单实例起步
> **目标**: 服务器以最小系统资源占用跑起来（≈1.5GB / 6 容器），扩容时**只加实例、不改代码**。

---

## 1. 背景与问题

现状 `docker/docker-compose.yml` 是"技术栈全能力验证"环境：**30 个容器、≈12GB 内存起步**
（6 Redis + 17 MySQL + ShardingSphere + Kafka/ZK + Prometheus/Grafana）。对"每天 1-2 小时、
单人开发"的场景，这个起步成本是巨大的浪费——**起步负载只有几十人，却按 5 万在线的上限规格铺满**。

### 1.1 红线合规声明（重要）

本方案**不是"单体架构"**，不违反任何红线：

- **红线"禁止单体架构"**约束的是*代码耦合*：模块必须高内聚、低耦合、可独立水平扩展。
- 本方案约束的是*部署数量*：进程形态不变（网关/游戏节点/数据服务仍是独立无状态进程），
  只是**起步只启动最少进程集**（各 ×1）。最小集依然是分布式（≥3 个进程），非单体。
- 分片/集群/读写分离/异步落库等**能力代码全部保留**，只是起步配置不启用，扩容时配置开启。

### 1.2 现状规模假设清单（已扫描确认）

| 组件 | 现状（Dev-Std） | 起步需求（几十人负载） | 差距 |
|------|----------------|----------------------|------|
| Redis | 6 节点 Cluster（3主3从） | 1 个实例即可 | 6× |
| MySQL | 8 主 + 8 从 + 1 全局（17 实例） | 1 实例承载 8 逻辑库 | 17× |
| ShardingSphere | 8 分片 + 8 读写分离组 | 8 分片无读写分离 | 连接池减半 |
| Kafka | 集群（+ZK） | **关闭**（同步回退已实现） | 免部署 |
| 监控 | Prometheus + Grafana | 关闭 | 免部署 |
| 业务进程 | 网关/游戏/数据各 1 | 各 1（不变） | — |

## 2. 三档配置矩阵（Scale-to-Fit）

| 维度 | **Dev-Mini 起步档** | **Dev-Std 全能力** | **Prod-50K 生产** |
|------|--------------------|--------------------|-------------------|
| 用途 | 日常开发 / 单机联调 / 原型验证 | 技术栈全能力验证（当前现状） | 5 万在线生产 |
| 容器数 | **6**（3 中间件 + 3 业务进程） | 30 | 100+ |
| 内存预算 | **≈1.5GB** | ≈12GB | ≈25GB+ |
| MySQL | 1 实例 · 8 逻辑分片库 + 1 全局库 | 8 主 + 8 从 + 1 全局（GTID） | 8 主 8 从 + 扩容 |
| Redis | 单实例（maxmemory 256MB） | 6 节点 Cluster | 16 分片 Cluster |
| ShardingSphere | 8 分片 · 无读写分离 | 8 分片 + 8 RW 组 | 8 分片 + 读写分离 |
| Kafka | 关闭（落库走同步回退） | 开（异步落库 + DLQ） | 集群（异步 + DLQ） |
| 监控 | 关闭 | Prometheus + Grafana | 监控告警全开 |
| 全局服务（5 个） | 不部署 | 按需 | 全量独立部署 |
| 网关 | 1 进程 | 1 进程 | 10 进程 |
| 游戏节点 | 1 进程 | 1 进程 | 50 进程 |

## 3. 核心设计：逻辑分片固定，物理拓扑渐进

**关键决策（2026-08-12 确认）**：MySQL 分片采用 **"逻辑 8 分片固定 · 物理实例 1→8 渐进"**。

```
起步（1 物理实例）                    扩容（N 物理实例）
┌──────────────────────┐          ┌─────────┐ ┌─────────┐ ┌─────────┐
│ mysql-mini :3306     │          │ shard0-1│ │ shard2-5│ │ shard6-7│
│  cami_shard_0..7 (8库)│  ===>    │ 搬库0,1 │ │ 搬库2-5 │ │ 搬库6,7 │
│  cami_global         │          │         │ │         │ │         │
└──────────────────────┘          └─────────┘ └─────────┘ └─────────┘
     SS: ds_0..7 → 同一 URL            SS: 仅改 dataSource URL，算法 %8 不动
```

- **为什么不是"起步 1 分片（%1）"**：取模分片从 `%1` 扩到 `%8` 必须改算法 + 全量数据重分布；
  而"逻辑 8 分片物理 1 实例"扩物理实例时**分片算法与业务代码零改动、数据零重分布**——
  每分片库只是"物理搬移"到新实例，SS 改一行 URL。
- 代价：起步建 8 个空库（一个实例内建 8 个库≈零额外成本，共享 buffer pool）。
- 扩容触发点：单实例连接数 / IO 成为瓶颈时（容量基线：单分库 9784 TPS，8 库单实例共享 IO，
  起步负载 TPS <100，余量 >50×）。

## 4. 各组件起步/扩容路径

| 组件 | 起步（Mini） | 扩容到 | 切换方式 | 数据迁移 |
|------|-------------|--------|---------|---------|
| MySQL | 1 实例 · 8 逻辑库 | 8 实例 · 每实例 1-2 库 | 新实例 + 搬库 + SS 改 URL | 逻辑备份/xtrabackup 搬库，无重分布 |
| Redis | 单实例（standalone） | Cluster（3 节点起） | `RedisBackend` mode 配置切换（待实现） | 无（缓存可冷启动重建） |
| 网关 | 1 进程 | N 进程 | 负载均衡 / SO_REUSEPORT | 无（无状态） |
| 游戏节点 | 1 进程 | N 进程 | Scene Scheduler 调度 | 无（Redis 快照重连） |
| Kafka | 关闭 | 开启 | 注入 `AsyncFlushSink`（代码已支持同步回退） | 无 |
| 监控 | 关闭 | 开启 | compose/K8s 服务启用 | 无 |
| 全局服务 | 不部署 | 按需 | 配置中心注册 | 无 |

## 5. 内存预算明细（Mini 档 ≈1.5GB）

| 组件 | 内存 | 说明 |
|------|------|------|
| MySQL ×1 | ~500MB | buffer pool 32M + 进程开销；8 库共享 |
| Redis ×1 | ~350MB | maxmemory 256MB + 进程开销 |
| ShardingSphere ×1 | ~400MB | JVM -Xmx256m + 连接池（maxPoolSize 2 × 8） |
| 网关进程 ×1 | ~100MB | io_context 池（可配置，起步 2 线程） |
| 游戏节点 ×1 | ~150MB | 场景线程（可配置，起步 1-2） |
| 数据服务 ×1 | ~100MB | gRPC + 落库代理 |
| **合计** | **≈1.6GB** | 单机 4GB 内存即可流畅开发 |

## 6. 落地文件

| 文件 | 说明 |
|------|------|
| `docker/docker-compose.mini.yml` | 最小档中间件栈（3 服务：mysql-mini / redis-mini / shardingsphere-proxy-mini） |
| `docker/shardingsphere/config-cami_db.mini.yaml` | 8 逻辑分片 → 单物理实例，无读写分离，连接池减半 |
| `docker/mysql/init-shard-mini.sh` | 单实例内建 8 分片库 + 全局库 + 循环建表 |
| `docker/docker-compose.yml`（保留） | Dev-Std 全能力档，技术验证用，与 Mini 并存 |

**用法**：
```bash
docker compose -f docker/docker-compose.mini.yml up -d          # 起步 ≈1.5GB
docker compose -f docker/docker-compose.yml up -d               # 需要全能力验证时
```
业务进程（网关/游戏/数据服务）在宿主机本地运行，连 `localhost` 映射端口（见 mini compose 注释）。
